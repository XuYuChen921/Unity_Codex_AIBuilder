# Unity 2022.3 角色剧情编排工具：开发计划 V1.0

项目：飞向蓝天的恐龙 2.0  
工具暂名：Creature Stage（角色剧情编排器）  
编制日期：2026-09-10  
需求依据：《Unity2022.3_角色剧情编排工具_详细开发文档_V1.0.md》  
文档状态：实施计划草案，供任务拆分、资源安排与阶段评审使用  
首个适配对象：中华龙鸟；辅助验证对象：科萌；复用验证对象：待选第二个地面角色

> 本计划依据需求文档编制，尚未检查实际工程、FBX 和目标设备。下文工期是附带前提的资源规划估算，不是开发承诺；算法效果、性能和素材可用性必须通过实际验证确定。需求文档中的示例时间表不作为已经批准的正式剧情。

## 1. 开发目标

在 Unity 2022.3 内交付一个可复用插件，让美术通过动作库、Timeline 和场景路径编辑，安排角色在指定时间完成动作、移动、转身和注视，并完成预览、问题定位、烘焙及运行时播放。

第一版的成功标准：

- 美术不写脚本，独立完成一段“待机 → 起步 → 行走或跑步 → 停稳 → 转身或低伏”的表演。
- 在已校准的素材和地形范围内，按时到位，脚部支撑稳定，骨架不出现明显翻折或拉伸。
- 正播、暂停和任意时间跳转能在批准容差内重现相同姿态与状态。
- 中华龙鸟、科萌和其他受控角色使用统一剧情时间；交互等待和事件触发规则明确。
- 修改素材、比例、路线或地面后，能够发现旧烘焙失效并阻止错误数据发布。
- 第二个地面角色能通过配置接入基本表演，目标平台完成构建与实际运行验证。

### 2.2 后续版本

批量文本语义导入、高级模板管理、精细脚趾接触、复杂四足步态、动态平台、专项滑翔、自动导航建议及高级局部动作叠加，列入后续版本。V1.0 可使用少量固定表演模板，但不以完善模板管理平台作为发布前提。

第一版只保证经配置和测试的静态地面、缓坡及小起伏范围。遇到断层、较大台阶、急弯、超限速度或缺失过渡动作，应明确报告问题。

## 3. 实施原则与技术约束

1. 先验证核心运动，再扩展美术界面。G1 未通过，不进入完整编辑器功能开发。
2. 保留源 FBX、骨架层级、蒙皮和原动画；需要清理累计运动时生成派生资产并验证。
3. 使用原生 Timeline 配合自定义轨道、片段、Inspector 和 Scene 手柄，不重做时间轴编辑器。
4. 角色世界位置和朝向只由一个运动系统写入；Animator、导航与既有脚本的控制权必须显式交接。
5. 剧情时间、路径距离、动画采样和脚接触由统一计划关联，不用独立脚本各自推进。
6. 先同步步态，再做接触和腿部修正；不能靠拉长腿、末帧瞬移掩盖时间距离冲突。
7. 先支持静态场景烘焙播放；预览和运行时遵循相同求值规则。
8. 引擎补丁与包版本以实际工程为准。候选依赖先在验证工程测试，不直接升级业务工程。
9. 源码检查、编译、运行、视觉及头显验收分别记录，不能互相替代。

## 5. G0：工程与素材摸底

目标：确认实际素材和工程能支撑方案，建立最小可重复验证环境。

| 任务 ID | 任务 | 负责人 | 交付与完成条件 |
|---|---|---|---|
| G0-01 | 收集引擎、依赖、渲染管线、平台和设备信息 | B、QA | CompatibilityReport，记录实际版本及设备矩阵 |
| G0-02 | 建立独立验证工程和 UPM 包骨架 | B | Runtime/Editor/Tests 分离，最小工程可编译构建 |
| G0-03 | 接入带网格中华龙鸟及核心动作 | A、TA | 模型、Avatar、Clip 引用正确，缺失素材清单明确 |
| G0-04 | 检查根运动、正向、单位、骨架路径和 HorseLink | A、TA | RigProfile 初稿、骨架映射和根运动报告 |
| G0-05 | 制作动画绝对时间采样与预览恢复原型 | A、B | 原生 Timeline、工具预览和 Play Mode 不重复驱动 |
| G0-06 | 明确质量测量方式与剧情待确认项 | QA、负责人 | QualityProfile 草案、冲突登记、G1 任务估算 |

最小素材集：带蒙皮模型、idle、walk、run、低伏和至少一条 90° 转身；同时核查起步、刹停、低伏进出过渡，以及源动作的累计位移和转角参考。

G0 验收：T01/T02/T20 的基础范围通过；明确哪些动作可直接用、哪些需要派生清理、哪些必须补制。拿不到关键素材时，可继续包结构和验证工具工作，但不能宣布骨架适配通过。

## 6. G1：核心运动验证

目标：只用最小测试场景，证明动作、路线、接触、骨架和任意跳转能协同工作。

| 任务 ID | 任务 | 前置依赖 | 负责人 | 交付与完成条件 |
|---|---|---|---|---|
| G1-01 | 实现 ActorProfile、ActionDefinition 和基础绑定校验 | G0 | A、B | 共享配置与场景实例分离，错误绑定可定位 |
| G1-02 | 建立内部校准台，录入周期、距离、接触和转角 | G1-01 | B、TA | 核心动作有可追踪的校准数据及源签名 |
| G1-03 | 实现路径世界弧长表、地面过滤与时间距离规划 | G1-01/02 | A | 输出 MotionPlan 和不可行原因，不擅改时间终点 |
| G1-04 | 实现距离驱动步态与基础起停、转身衔接 | G1-02/03 | A | 动画采样随实际距离一致变化，倍率不超批准范围 |
| G1-05 | 实现接触锚点及 HorseLink 求解原型 | G1-02/04 | A、TA | 平地与缓坡接触稳定，骨长和弯曲方向有效 |
| G1-06 | 接入统一时钟、绝对采样和求值顺序 | G1-03/04/05 | A | 支持随机 Seek、暂停及重复 Evaluate |
| G1-07 | 建立误差采集、失败场景和初步设备测量 | G1-06 | B、QA | 有数据与画面对照，形成 G1 验收报告 |

实施顺序：先平地直行，再起停，再原地转身和低伏，最后缓坡与接触切换。分段 HorseLink 方案不稳定时，对比带约束的完整链求解；保留实验结果，选择经测试的方案。

G1 最小演示包括：正常速度行走、不同合法距离/时长、故意不可行的高速移动、起停、转身、低伏和一段缓坡。重复执行 0 → 90 → 35 → 68 秒跳转测试；测试序列长度必须覆盖这些时间点。

G1 验收重点：T03–T11 中的核心范围。质量阈值由实际测量和 TA/负责人评审确定并固化；不得只凭“角色能动”通过。核心效果失败时回到校准或求解器调整，并同步更新排期。

## 7. G2：美术编辑闭环

目标：将已经验证的能力变成美术可独立使用的工作流。

| 任务 ID | 任务 | 负责人 | 交付与完成条件 |
|---|---|---|---|
| G2-01 | 完善中文动作库、搜索、分类和预览 | B | 保留源文件名，能找到并拖入已校准动作 |
| G2-02 | 实现 Timeline 表演轨及阶段 Inspector | B、A | 编辑开始/结束、起停阶段和同步策略后重算 |
| G2-03 | 实现路径、终点、朝向和锚点 Scene 工具 | B | 地面建点、拖动、吸附、继承和局部覆盖有效 |
| G2-04 | 实现片段移动、拉伸、裁剪、拆分和复制语义 | B、A | 时间与源采样区间不混淆，拆分接触连续 |
| G2-05 | 实现诊断定位及固定玩家参考窗口 | B | 能跳到问题时间并选中片段，可检查遮挡时段 |
| G2-06 | 完善预览快照、控制权恢复和 Undo/Redo | B、A | 停止、切场景、重载和异常退出后正确清理 |
| G2-07 | 实现编译烘焙、依赖签名与发布拦截 | A、B | 源变化使缓存失效，阻断错误不能进入正式构建 |
| G2-08 | 组织美术独立试用并修复主要阻塞 | 美术、QA | 从空序列完成短表演、定位错误、修正、烘焙 |

本阶段使用轻量内部校准台升级为可维护的配置工具，不要求先完成复杂自动识别。可见性计算应配合固定玩家窗口人工复核，尤其是透明植被和碰撞体不一致的区域。

G2 验收：T13/T14/T16/T20，以及片段编辑后的 T03/T10/T11 回归。美术试用必须包含一次故意配置错误及修正过程，不能只播放预制演示。

## 8. G3：真实剧情试点

目标：接入已批准的中华龙鸟剧情，验证多角色、状态事件和交互体验。

| 任务 ID | 任务 | 负责人 | 交付与完成条件 |
|---|---|---|---|
| G3-01 | 整理正式时间表、站位和路线 | 负责人、美术 | 解决总时长、左右藏点及运镜冲突，保存批准版本 |
| G3-02 | 分段编排中华龙鸟剧情 | 美术、TA | 每段动作、路径、衔接和可见性可单独验收 |
| G3-03 | 接入科萌 Hover、注视及猎食者运动 | A、美术 | 使用统一时间；互看无同帧循环依赖 |
| G3-04 | 实现可逆状态与一次性事件适配 | A | Seek 恢复状态；收集等副作用不重复触发 |
| G3-05 | 实现并验证交互等待规则 | A、QA | 明确 FixedDeadline 或 PauseSequence；追踪不被暂停 |
| G3-06 | 完成全段烘焙、可见性检查和真实场景试用 | B、QA、美术 | 形成剧情试点报告及问题清单，关闭阻断项 |

文档里的 132 秒只能作为待确认示例；实际制作以 G3-01 的正式时间表为准。若两种等待策略都对外提供，两种都必须测试；若第一版只支持其中一种，需明确锁定产品范围。

G3 验收：T12/T15/T16/T17 及全段时间、姿态回归。分别检查无输入、及时输入、等待后输入与超时；含等待的实际体验时长按所选策略报告。

## 9. G4：复用与发布

目标：验证插件不依赖首只恐龙和开发机，并形成完整交付包。

| 任务 ID | 任务 | 负责人 | 交付与完成条件 |
|---|---|---|---|
| G4-01 | 接入第二个地面角色及同角色双实例 | TA、A | 基本表演通过配置完成，实例数据不互相污染 |
| G4-02 | 在目标平台构建并实机运行 | QA、A | 无 Editor 依赖，离开相机再返回后状态正确 |
| G4-03 | 测量并优化性能及缓存体积 | A、QA | 记录 CPU 分项、GC、内存、Seek 耗时和烘焙体积 |
| G4-04 | 完善配置迁移、失效检查和异常恢复 | B、A | 版本变化有明确迁移或重建路径，异常资源可回收 |
| G4-05 | 全量执行验收矩阵并修复缺陷 | QA、全体 | T01–T20 完成，阻断问题关闭，剩余警告登记 |
| G4-06 | 整理包、样例、操作文档和培训录屏 | B、TA | 干净工程按文档完成安装、编排、烘焙及播放 |

性能负载先覆盖项目实际并发角色数，再按需要测 3/6/12 角色压力点。这些压力点用于测量，不代表承诺支持数量。Editor 与 Player 数据分开报告，目标设备刷新率与预算以 G0 确认结果为准。

G4 验收：T18/T19 和完整回归。实际设备上的画面与交互必须单独签收；仅构建成功不能发布为已完成设备验收。

## 10. 关键依赖与协作安排

关键路径：

```text
真实素材与工程版本
  → 骨架/根运动检查
  → 动作距离和接触校准
  → 路径时间规划 + 步态同步
  → 接触/HorseLink + 绝对时间求值
  → G1 技术验收
  → 美术编辑与烘焙闭环
  → 正式剧情、多角色与交互
  → 第二角色、实机回归与发布
```

允许并行的工作：

- G0：工程初始化与素材检查并行；负责人同步确认平台和剧情问题。
- G1：A 开发运动核心，B 完成内部校准台与诊断，TA 校准动作，动画师补素材。
- G2：核心接口稳定后，Timeline/Scene 编辑与烘焙实现可协作推进，持续集成验证。
- G3：程序接入多角色和事件，美术分段排演，QA 分段回归。
- G4：文档与设备测试并行，缺陷修复后按影响范围回归。

动画补制要进入独立任务清单，记录需求姿态、支撑脚、预计时长、交付日期及受影响阶段。不能把待补动作隐含在程序任务中。

### 11.2 验证方式

- EditMode：验证时间距离映射、相位连续、数据校验、依赖签名和失效检测等纯数据逻辑。
- PlayMode：验证动画求值、随机 Seek、事件去重、多角色同步及预览/运行切换。
- 编辑器操作：实测路径编辑、撤销重做、复制拆分、保存重开、关闭窗口及脚本重载。
- 视觉检查：保留原动画、参考移动和修正后的同机位对照，重点查看脚滑、翻膝、起停和低伏。
- Player/设备：验证目标构建、实际画面、交互等待、相机裁剪恢复和性能。

### 11.3 质量指标建立方式

G0 定义测量方法；G1 以真实素材测量、讨论并批准数值。以下指标不能直接填入未经验证的统一阈值：

| 指标 | 记录内容 | 批准依据 |
|---|---|---|
| 到达误差 | 终点距离、朝向差、到达时间差 | 剧情站位与镜头要求 |
| 支撑滑移 | 承重期接触区域的地面切向位移与峰值 | 模型比例、动作类型、近景效果 |
| 骨架稳定性 | 骨长误差、关节超限、翻折和过伸 | 骨架实测与 TA 审核 |
| Seek 一致性 | 顺播与跳转的根位姿、骨骼姿态及状态差 | 采样精度和动作误差容限 |
| 可见性 | 头/躯干被遮挡的时间段及人工复核结果 | 正式剧情的关键可见时段 |
| 性能 | CPU P50/P95/P99、GC、内存、Seek 耗时、缓存大小 | 目标设备和并发负载 |

每次阶段验收记录代码版本、素材签名、配置、测试场景、运行环境、实测结果、截图或视频，以及未通过项目。发生影响效果的改动时，重跑对应测试和关联用例。

## 12. 风险与处置

| 风险 | 识别节点 | 处置 | 对计划的影响 |
|---|---|---|---|
| 原地动画缺少位移/接触参考 | G0/G1 | 内部校准台估计并人工审核，优先取得源数据 | 增加 TA 工时，可能阻塞步态验证 |
| HorseLink 求解破坏低伏或转身 | G1 | 对比分段与完整链约束求解，实测选型 | 使用技术预留，必要时重新排期 |
| 起停与低伏过渡缺失 | G0 | 提前开动画补制任务 | 未交付前不能完成对应动作验收 |
| Timeline、Rig 或既有控制器双重驱动 | G0/G1 | 建立唯一 Host 和控制权交接，固定包版本 | 阻断核心集成，不带缺陷进入 UI 扩展 |
| 正式剧情时间、左右或交互规则冲突 | G0/G3 | 负责人明确版本，保留冲突登记 | 影响正式排演；不阻塞通用技术验证 |
| 路线、比例或地形改动未触发缓存失效 | G2 | 纳入依赖签名并做故意修改测试 | 未修复不得正式发布 |
| 透明植被造成遮挡检查误判 | G2/G3 | 配置代理并固定机位人工复核 | 增加场景设置与复核工作 |
| 目标设备性能不足 | G1/G4 | 提前测量，优先烘焙与已验证的视觉降级 | 超出预算时调整负载或方案后重验 |
| 第二角色需要大量专用代码 | G4 | 检查可配置边界，区分骨架适配与通用逻辑 | 复用验收失败，不能只以首角色发布通过 |

## 13. 项目管理与变更规则

每个开发任务至少记录：任务 ID、负责人、依赖、输入素材、交付物、验收方法、状态和阻塞原因。任务状态统一为：待开始、进行中、待验证、已完成、阻塞。

每周安排一次可运行演示和问题评审，检查本周交付、验证证据、素材缺口及下一周依赖。G0–G4 设置正式阶段评审，未满足出口条件不自动进入下一阶段。

需求变化先评估影响的功能、资产、测试与排期。影响 V1.0 范围、正式时间表、用户交互或质量门槛的变更，由项目负责人确认并更新计划版本；普通实现细节由技术负责人按现有范围推进。

缺陷分为：

- 阻断：不能构建/播放、源资产污染、崩溃、错误事件副作用、明显姿态破坏、失效缓存被发布等。必须修复。
- 重要：核心工作流不能完成或明显质量不达标。发布前关闭，或经评审明确调整范围后重验。
- 一般：不阻塞工作流的体验和表现问题。登记负责人及处理版本，保留问题说明。
